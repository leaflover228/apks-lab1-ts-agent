# Журнал взаємодії з AI

Використовуйте цей шаблон для документування запитів до AI, ключових рішень і прийнятих або відхилених пропозицій.

## Запис 1 — Початкове створення агента

- **Запит:** Створити у репозиторії custom agent Build Engineer для кросплатформного TypeScript Hello World із npm scripts, Vitest і CI для Windows, Linux та macOS.
- **Відповідь AI (суть):** Підготовлено manifest агента з роллю, відповідальністю, правилами роботи з файлами, заборонами, порядком роботи та критеріями успіху.
- **Проблема:** Початковий репозиторій не містив конфігурації агента, skills чи prompts, тож потрібно було визначити структуру й не припускати наявності суміжних файлів.
- **Рішення:** Додати окремий manifest у `.github/agents/build-engineer.agent.md`, спершу перевіривши стан репозиторію.
- **Прийнято/відхилено і чому:** Прийнято — manifest задає обмежену роль і перевірні критерії для потрібного build/CI workflow.

## Запис 2 — Розділення skill на три

- **Запит:** Розділити загальний skill TypeScript Hello World на три skills: `project-scaffold`, `build-and-test` і `github-actions`; старий skill не видаляти.
- **Відповідь AI (суть):** Створено по одному `SKILL.md` для scaffold, збірки/тестування та GitHub Actions із відповідними входами, виходами, кроками, перевірками й правилами ідемпотентності.
- **Проблема:** Один загальний skill об'єднував різні етапи роботи й не відповідав структурі лабораторної, що вимагала три спеціалізовані skills.
- **Рішення:** Перенести корисні інструкції у три нові skills, а старий файл залишити без змін.
- **Прийнято/відхилено і чому:** Прийнято — розділення дає кожному етапу власні точні інструкції; старий skill наразі збережений, щоб не втратити попередній вміст.

## Помилка і виправлення

- **Помилка:** У попередній версії в описах і документації залишалися placeholder-значення для ПІП і групи, а також не було чіткого запису про відновлення legacy skill і виправлення причин конфліктів між prompt/skill інструкціями.
- **Виправлення:** У [README.md](../README.md) замінено placeholder на `Ящук Георгій Олегович` і `КІ-405`. У цьому журналі додано секцію з описом проблеми та рішення, а legacy compatibility skill `.github/skills/typescript-hello-world-build/SKILL.md` відновлено для сумісності з попередніми процесами.
- **Помилка:** У старій схемі `git-init` було тлумачено як автоматична ініціалізація репозиторію, хоча за вимогами команда має лише перевіряти Git-репозиторій і готувати `.gitignore` без `git init`.
- **Виправлення:** Відкориговано опис команд і документацію: `git-init` тепер чітко говорить, що виконувати `git init` потрібно вручну, а сама команда лише перевіряє стан репозиторію і доповнює `.gitignore` без автоматичних змін.
- **Помилка:** У workflow/skill інструкціях траплялися суперечності щодо виклику Unix-скрипту: в одному місці використовувався прямий `./ci.sh`, а в іншому — `bash ./ci.sh`.
- **Виправлення:** Узгоджено вимоги: workflow повинен викликати `bash ./ci.sh` на Unix та `ci.bat` на Windows, щоб уникнути залежності від executable bit у Git.
- **Помилка:** Часом збірка або build/test команди могли запускатися без перевірки на наявність lockfile/зависностей.
- **Виправлення:** Вказано, що за відсутності `package-lock.json` або після зміни `package.json` спочатку виконується `npm install`, а при узгодженому стані — `npm ci`.

## Запис 3 — Перейменування оркестратора на project-init

- **Запит:** Усунути конфлікт між workspace prompt оркестратора та вбудованою командою Copilot `/init`; оновити посилання в агенті, prompts і документації.
- **Відповідь AI (суть):** Prompt оркестратора перейменовано на `.github/prompts/project-init.prompt.md`, а виклики, списки команд і документацію узгоджено з назвою `/project-init`.
- **Проблема:** Назва `/init` збігалася з вбудованою командою Copilot (Initialize Copilot instructions), тому Copilot перехоплював виклик замість запуску workspace prompt.
- **Рішення:** Використовувати `project-init` як ім'я workspace-команди, зберігши роль `init` з методички; додати примітку в архітектуру та залишити згадку `/init` лише як пояснення конфлікту.
- **Прийнято/відхилено і чому:** Прийнято — унікальне ім'я `/project-init` відрізняється від вбудованої команди й однозначно запускає потрібний orchestrator.
